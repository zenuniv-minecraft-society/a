# Information Architecture

## 方針

root READMEは、マイクラサークルの概要が普通に読める入口にします。活動記録、判断、運用、根拠は `docs/` 配下へ分けます。

## 構成

- `docs/community/`: 人、連絡場所、参加導線、役割
- `docs/servers/`: 複数サーバー前提のカタログとサーバー別情報
- `docs/events/`: 定期イベントと企画の型
- `docs/activity/`: 活動記録と時系列ログ
- `docs/operations/`: 問い合わせや運用情報
- `docs/decisions/`: 構造や方針の判断
- `docs/reference/`: 用語と参照元
- `docs/repository/`: このリポジトリの保守ルール

## 理由

- 初めて見る人には、リンク集だけではなくサークルの雰囲気と主要情報が必要。
- `lkjmc` はサークルのサーバーの一つであり、ほかのサーバーも追加できる形にしたい。
- 活動記録はroot直下ではなく、docsの一部として扱う方が拡張しやすい。
- 編集するとき、概要、記録、判断を分けた方が迷いにくい。

## 採用しなかった形

- root直下に `timeline/` を置き続ける: 入口が増えすぎる。
- `server/` 単数形で管理する: `lkjmc` 以外のサーバーを追加しにくい。
- READMEを表だけのリンク集にする: サークル情報が伝わりにくい。
- READMEに細かい接続先詳細だけを詰める: 更新漏れと誤情報が増えやすい。
